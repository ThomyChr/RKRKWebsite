# PHP 8.0 Kompatibilität

Ziel-Laufzeit: **PHP 8.0**. Kein Sprung auf 8.2/8.3 in derselben Welle (strengere Deprecations, z. B. dynamische Properties).

Milestone **M2** ist rein technisch: Verhalten gleich, Fatals weg. Keine UI- oder Pfadänderungen in denselben PRs.

## Bekannte Risikoklassen in diesem Code

| Thema | PHP 8 | Vorkommen hier |
|---|---|---|
| `each()`, `create_function()`, `split()`, `mysql_*`, `ereg*` | entfernt | in aktiven App-Dateien nicht gefunden |
| `$str{$i}` String-Offset | entfernt | in `scripts/rkrk_gen_newaccess*.php` (Kopien); aktives `rkrk_gen.php` aktuell ohne Treffer |
| `null` an `strpos`, `strtolower`, `htmlspecialchars`, `explode` | TypeError / Deprecation je nach Minor | häufig bei fehlenden GET-Keys; teils schon `?? ''` in Access-Control |
| Undefined array key | Warning | `GetURLwDefault_Lower()` nutzt `$SecParamters[$SecParameter]` ohne `isset`, wenn `$SecUrl` wahr ist |
| `implode($glue, $array)` | OK in 8.0, wenn `$array` Array ist | CSV-Schreiben in Access-Control |
| Optionale Parameter vor Pflichtparametern | Deprecation | beim Anfassen von Funktionsköpfen prüfen |
| Vendor `rt/dompdf` | oft schon 7.4/8-tauglich | nicht Erstziel; nur anfassen bei nachgewiesenem Fatal |

## Vorgehen in M2 (kleine PRs)

1. **Syntax:** `php -l` auf allen aktiven `*.php` ausser `vendor/`, `fpdf/tutorial`, datierten Kopien.
2. **Kern-Includes zuerst** (ein Issue/PR):  
   `scripts/rkrk_gen.php`, `scripts/rkrk_gen_ext.php`, `scripts/rkrk_menu.php`, `rkrk_access_control.php`, `scripts/rkrk_csvfiles.php`.
3. **Öffentliche Vier** (eigenes Issue, Label `constraint-public-api`): nur Null-Sicherheit und Warnings, kein HTML.
4. **Restliche Einstiegspunkte** wellenweise wie M5, aber **nur** PHP-8, solange M2 offen ist.
5. Runtime: Seite unter PHP 8.0 öffnen, `display_errors` auf test, Error-Log sammeln.

Typische sichere Änderung:

```php
// vorher
$Value = strtolower($SecParamters[$SecParameter]);
// nachher
$Value = strtolower((string)($SecParamters[$SecParameter] ?? ''));
```

Keine Umbenennung von Funktionen, keine neuen Namespaces in M2 (erschwert das Diff-Review).

## Explizit nicht in M2

- `declare(strict_types=1)` flächendeckend (zu viele implizite Casts).
- Composer-Autoload für die Alt-App.
- Löschen der `*_newaccess*` und `* - Kopie*`-Dateien (das ist M7) — sie dürfen unter PHP 8 kaputt bleiben, solange niemand sie inkludiert.
